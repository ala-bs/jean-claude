# Keyboard Shortcuts

Single source of truth for every key binding in the renderer. **Check this file
before adding a shortcut, and update it in the same change.**

Regenerate the table below from source:

```bash
node scripts/list-shortcuts.mjs --write    # regenerate the table below in place
node scripts/list-shortcuts.mjs --check    # list candidate collisions (exit 1 if any)
node scripts/list-shortcuts.mjs            # print the table to stdout
```

The table between the `GENERATED` markers is written by the script — edit the
source, not the table.

## How dispatch works — read this before picking a key

`src/common/context/keyboard-bindings/index.tsx` walks registered bindings
**LIFO with no layer precedence** when no exclusive layer is mounted, and
`tryHandleBinding` calls `preventDefault()` and stops at the first match.

The practical consequence: **the component that mounts last wins.** A binding
registered in a deeply-nested component silently shadows an identical binding
registered at the route root. "It's in a different scope" is *not* enough — the
scopes must be genuinely unable to co-mount.

Two bindings on the same key are fine when:

- One is inside a modal/overlay that takes an exclusive layer (`escape`,
  `cmd+enter` in confirm dialogs, palette navigation keys).
- They belong to overlays that are mutually exclusive by construction (only one
  overlay is open at a time — see the `overlays` store).

They are **not** fine when both surfaces are visible together — e.g. the feed
list and an open task panel.

## Reserved — never bind these

| Key | Owner |
| --- | --- |
| `cmd+q`, `cmd+h`, `cmd+m`, `cmd+w` | macOS system / window management |
| `cmd+r`, `cmd+shift+r` | Electron default menu (reload / force reload) |
| `cmd+shift+i`, `cmd+shift+c`, `cmd+shift+j` | DevTools |
| `cmd+shift+q`, `cmd+shift+z`, `cmd+shift+v` | macOS logout / redo / paste-and-match |

`cmd+w` is a partial exception: `electron/main.ts:138-175` strips the accelerator
from the default "Close Window" item, which is why `task-panel` can use it.

## Known collisions

Verified as **benign** (scopes cannot co-mount): `escape`, `enter`, `up`/`down`/
`left`/`right`, `cmd+enter`, `cmd+up`/`cmd+down`, `cmd+backspace`, `cmd+b`,
`cmd+e`, `cmd+m`, `cmd+n`, `cmd+p`, `cmd+shift+f`, `cmd+shift+w` — each pair is
overlay-vs-panel or dialog-vs-dialog.

Genuinely **suspect** (both surfaces can be on screen at once — the feed list
stays mounted behind an open task):

| Key | Conflict |
| --- | --- |
| `cmd+shift+p` | `feed-list-navigation` "Toggle Pin" vs `worktree-actions` "Create Pull Request" |
| `cmd+shift+d` | `feed-list-navigation` "Dismiss Item" vs `task-panel` "Cycle Diff Mode" |

Neither is currently fixed. Do not add to this list.

## Adding a shortcut — checklist

1. Run `node scripts/list-shortcuts.mjs --check` and read the table below.
2. Confirm the key is not in **Reserved**.
3. If the key already appears, prove the two scopes cannot be mounted together.
   If they can, pick a different key.
4. Register it via `useCommands(scope, [...])` with a `label` and `section` so it
   shows up in the command palette.
5. Run `node scripts/list-shortcuts.mjs --write` and commit the updated table.

## Free keys

Unbound and not reserved as of the last regeneration:

`cmd+g`, `cmd+y`, `cmd+shift+h`, `cmd+shift+x`

Do **not** trust this list without re-running the script — it is the part of
this doc most likely to be stale. `cmd+i` and `cmd+t` were listed here once and
were wrong: both are bound via a `shortcut` **prop** on `ModeSelector` /
`BackendModelPresetPicker` rather than a `shortcut:` object literal, so a naive
grep misses them. That is why the extractor now treats any JSX `shortcut="..."`
as a real binding unless the component is known display-only.
